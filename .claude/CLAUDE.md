# WHY

anyhost keeps every Claude Code and Codex session of every machine the Architect works on in Cloudflare R2, lists every session on every machine, and resumes a session on any machine from R2 alone, so a dead or busy machine never holds his history hostage.

# Facts

- The repository root is a cmod mod: `src/mod.ts` is the `defineMod`, `hooks/register.ts` only registers it, and `tests/` holds its `bun test` suite. `node_modules/@cmodjs/core/docs/` is the cmod documentation for the installed version.
- `cli/` is the `anyhost` program, TypeScript on Bun with its own `package.json`, `bun.lock` and `tsconfig.json`. `bun run --cwd cli build` compiles `cli/dist/anyhost-<os>-<arch>` with `bun build --compile` for each machine in `CMOD_MACHINES`, or all four, as cmod builds its own program, and runs `bun install` first. `bun run --cwd cli check` type-checks it. Both run `bun run --cwd relay build` first, which writes `relay/dist/relay.js`, the relay that `cli/src/connect.ts` carries as text and uploads, so a bare `bun test` fails before one of them ran. `bun test` at the root runs the mod's tests and `cli/tests/`, while `cmod check .` runs only the mod's.
- `package.json` `cmod.program` names `anyhost`, and `cli/package.json` names `bun run build` as its build, so `cmod publish` attaches `anyhost-<os>-<arch>` for darwin and linux on arm64 and x64 to each GitHub release, `cmod install` downloads it, and `cmod link` builds it from the checkout.
- The program reads its version from `.claude-plugin/plugin.json` at build time, so a release raises only that file's `version`.
- A push to `main` runs `.github/workflows/ci.yml`, which tests and, when the tag `v<version>` is missing, runs `cmod publish`. `docs/releasing.md` holds the steps.
- The program is the only code that talks to the relay, through `cli/src/relay.ts` alone, which compiles against `relay/protocol.ts`. Each program process, the service and each command, keeps one WebSocket to the Pool: it pings every 30 seconds, counts a pong more than 40 seconds late as a drop, and opens again at once, then after 1, 2, 4 and up to 60 seconds. `Relay.run` packs ops into requests of up to `MAX_OPS` and `MAX_MESSAGE_BYTES`, sends a put over 1 MiB as `PUT /v1/objects/<key>` beside them, and reads a get the answer had no room for with `GET /v1/objects/<key>`, which goes on with `Range` from the byte a broken download reached. A request with no answer goes again on the next socket, and a put whose condition failed while the object's etag is the md5 of its own bytes counts as written. The service waits out an outage; a command fails its requests once a connect fails, with the relay's address and the reason.
- The relay's address is `url` in `relay.json` in the state folder, and the device token the cmod secret `token` (`cmod secret get anyhost token`), both read again at each connect, so a machine joined while the service runs connects within a minute. With neither, the service keeps its queue and uploads nothing, its `/status` says the machine is not joined, and every command fails saying so. Tests and test machines use the test relay `anyhost-test-relay`, bound to the bucket `anyhost-test`, never `anyhost`.
- `anyhost.db` keeps the bucket the relay's welcome names, and a welcome that names another drops its tables and the state folder's `code/`, because journal ends and uploaded code parts belong to one bucket. `anyhost serve` then exits, and its service starts it on the new bucket.
- The relay closes a refused socket with a code: 4401 for an unknown token, 4403 for a removed machine, 4409 for a machine whose id another name holds connected, as a clone's original does. The program captures nothing then, and its `/claims/<session>` answer carries the reason, with `cloneFixFor` from `relay/protocol.ts` for a clone, which the mod shows as an error toast once a session. A machine renamed in cmod connects under its new name, which the relay takes.
- A write gets 120 seconds and as long again as its bytes take at 100 KB/s, since a 50 MB frame outlived 120 s on a Mac whose uploads moved at 0.4 to 0.9 MB/s. The limit stays total, because Bun never ends an upload that stopped moving. A download that moves no byte for 30 seconds goes on in its next try.
- The mod runs `anyhost serve` as an `isService` program job with `device.read()` in `ANYHOST_DEVICE_*`: cmod makes it a launchd agent on macOS or a systemd user service on Linux, which starts at login with no Claude Code open. The service's environment is `HOME`, `XDG_DATA_HOME`, `CLAUDE_CONFIG_DIR`, a fixed `PATH` and the job's `environment`, never the shell's or Claude Code's, so the program reads every setting from cmod options, not the environment. Every other command reads the machine from `cmod device --json`, through `~/.local/share/cmod/programs/cmod`, else the `cmod` on `PATH`, so it works with no session open. An open Claude Code session's cmod starts a stopped service again within 2 seconds, so a test of a stopped service closes every Claude Code on that machine first.
- A session is every file `transcript.ts` `ownerOf` names for it: Claude Code's transcript, everything under `projects/<folder>/<session>/`, `file-history/<session>/`, `tasks/<session>/` and `tasks/session-<8 hex>/`, `session-env/<session>/`, `jobs/<8 hex>/state.json`, background output at `<temp root>/<folder>/<session>/tasks/*.output`, the plans its transcripts name in `planFilePath`, the `paste-cache/<hash>.txt` its history lines name, and its lines of `history.jsonl`; Codex's rollout, its lines of `history.jsonl` and `session_index.jsonl`, and its `state_5.sqlite` `threads` row as JSON. The 8 hex digits of `tasks/session-*` and `jobs/*` are the session id's first 8.
- A session's journal is records `{"device","path","at","size","after"}` plus `size` bytes: the file at `path` becomes its first `at` bytes plus the record's. `at` and the journal's sizes count the journal's bytes, and `after` is the size and sha256 of the file as its writer had it, which differ from the journal's after a restore rewrote another machine's paths. A record whose `path` ends in `/` holds that working folder's code header from `code.ts`, and one at `anyhost:code/<session>/parts/<sha256>` a part the header names, which no machine holds as a file. A record whose `after` is null, with `at` and `size` 0, says its writer's file is gone: the program writes one when the watcher or the 60-second backup finds a file it captured gone, never for a lines file or Codex's database, and replay removes the file until a later record brings it back. Each upload is one independent zstd frame at `journals/<session>/hot/<start>.zst`, written with If-None-Match.
- The journal is the chain of frames from byte 0, each starting where the one before it ends. A frame off the chain is one its writer put up while an earlier position failed: a restore skips it and ends at the first position no frame holds, its writer's next upload writes over it, and a seal deletes it. `chainOf` reads frames of up to 1 MiB together in one request, and a larger one by HTTP, at most 16 requests ahead, for a restore and for a seal, since a session at `uploadEvery` 0 has a frame per line, and a seal that fetched 1110 frames at once held every connection, so every upload on the machine timed out connecting once a minute.
- The program captures a session once the watcher names one of its files while the program runs, every file from byte 0, and never reads old, unchanged files. A lines file (`history.jsonl`, `session_index.jsonl`) names the sessions of the lines past its offset in the `line_offsets` table, which starts at the file's end on the first start. Historic sessions reach R2 through a one-time import outside anyhost.
- The upload queue in `serve.ts` drains every `uploadEvery` seconds, or on each write at `0`, with one upload in flight per session. A drain is one request of every queued session's frames, after each session read what its files gained, and the first drain of each session since the program started claims it in that request, before its frames, so a takeover tells this machine. The queue drains only while the relay is connected, and at its welcome. At `0` a failed upload tries again after 1 second, then twice as long each time up to a minute. The program reads `uploadEvery` from `cmod options anyhost --json` at start and every 60 seconds, because one program serves every session and a service keeps the environment it started with. An option the person never set is absent there, and the program uses `5`, as the mod's default says: replayed from the Architect's Mac's transcripts of 2026-10-06 to 2026-11-05, every write takes 1,258,076 uploads, past R2's free 1,000,000 Class A requests a month, and 5 seconds 411,952.
- After an upload that changed a session's files, `captureCode` reads its working folder in the background: one read per session, none while the last read's records still go up, and one more once they are up when the session changed meanwhile. The code goes up in later drains than the files, every part before the header that names it, and a part stays in `codeWaiting` until R2 has it, because `captureCode` counts every part it returned as written. At `uploadEvery` 0 a drain that carries a file's change carries no code, and a drain of code puts up to `CODE_PIECES` (4) frames of at most `CODE_PIECE_BYTES` (128 KiB) at once, and the journal counts them up to the first that failed. From a test machine whose link takes about 1.2 MB/s, 16 MiB of code catches up in 31 to 45 s, against 86 s one 256 KiB piece at a time, and a line still reaches R2 in about 1 s while the session's repository commits. 8 pieces at once fill that link, and lines wait past 2 s. At N seconds a drain carries all the code waiting. A working folder missing on this machine gets one log line and no code, and the session's files still go up.
- Every 60 seconds the program stats every file of the sessions it captures, queues the ones whose size or modified time moved, writes `index.json` when it changed, and seals each session quiet for 10 minutes. An upload writes `index.json` at once when its session is new or moved to another working folder or repository, because a restore reads where the session goes from the index. At start the program stats the watched folders and queues the files changed since the `heartbeat` file's modified time, which it touches every 60 seconds.
- A drain with no file change and no code waiting sends nothing, not even the claim check. A JSONL file uploads whole lines only, so a line Claude Code is still writing waits for its end. An empty file is a record too, as a background command's output before its first line, except a lines file's view of a session with no line in it.
- `/status` lists only the problems that hold now: each is keyed by the file or the step that failed, and leaves once that file or step works again.
- Codex 0.166 names a thread from its `state_5.sqlite` `threads` row's `name` alone, and writes each name to `~/.codex/session_index.jsonl` too, not to its transcript, so a Codex session's title comes from that file. On a machine Codex never ran on, Codex makes the row at its first start with no name and names the thread anew after the next turn. So when Codex writes its database or its write-ahead log, the program reads the row of each session a restore placed whose row it has not read since (`files.mtime` 0), and puts the latest `session_index.jsonl` name into a row with none, before Codex's screen loads the thread.
- Claude Code writes `~/.claude/projects/<working folder with every character but letters and digits as ->/<session>.jsonl`, and a subagent's transcript under `<session>/subagents/`. Codex keys a session by the uuid at the end of its `rollout-*.jsonl` name. Claude Code writes one session id into a second project folder when a session is forked or resumed from another working folder (on this Mac 1 of 5426 ids, a one-line `history-suppression` file): both files are records of the session's journal at their own paths.
- A log (`.jsonl`, `.output`, a lines file's view) uploads what it gained. A log whose last 32 bytes before its uploaded end changed, or whose bytes no longer hash to its last record's sha256, uploads whole, as does every other file whenever its sha256 changes.
- The program keeps each file's journal and local sizes, last 32 bytes and sha256, each journal's end and sealed position, and each session's index entry in `~/.local/state/anyhost/anyhost.db`, which `anyhost resume` writes too. `pragma user_version` 2 is this shape: a database of another version is dropped and made again, since anyhost 0.1's segment offsets have no use here.
- The claim holder writes the journal. Every frame is a put with the session as `holder`, which the relay refuses with 409 once another machine holds the session, and a machine whose write at a position is refused with other bytes there stops the session in `journals.stopped` and logs the fork. `anyhost resume` stops the session there too while it places files, so the watcher never uploads a half-placed session.
- `anyhost resume` takes a session only the machine it started on lists in its index, as that machine holds it by capture alone, and needs `--take` once another machine resumed the session, which lists it from then on: a restore writes this machine's index at once.
- Restore keys a replayed file by its path relocated to this machine, so records two machines wrote at their own paths land in one file, checks each file against its last record's `after` as that record's writer had it, then places it with `relocate`, emptying any copy this machine already has, and puts the code back with `restoreCode`, whose answer is the folder the session continues in. A lines file's view is never checked, because its writer's view can hold lines the journal never got, such as the prompt a machine takes before it hears of a takeover: placing it appends the session's lines this machine lacks. A `file-history/` backup of a file under Claude Code's or Codex's own folders, such as a plan, is relocated as that file is, and a Codex `state_5.sqlite` row goes in only when that database exists. A file a deletion record removed is removed here too. A repository this machine lacks is cloned into the `checkouts` option's folder, else the folder the checkouts of this machine's sessions share, else the home folder. A working folder outside git goes where `relocate` moves its path, so a session in the writer's temp root, such as a scratchpad, continues in this machine's.
- A takeover is a `claim` with `take`. The Pool sends `released` to the old holder's sockets, or keeps it for that machine's next welcome, which the program reads before anything uploads, and every program process writes it into `journals.holder` at once, so the next prompt there is refused. A claim answered `told: false` writes the old holder's name to `journals.untold`. The program answers it once on `/claims/<session>`, and the mod shows it as a warning toast in the session `anyhost resume` opened: that machine may take one more prompt before its program connects.
- `relocate` rewrites every occurrence of the writer's roots at a path boundary: its home, Claude Code's folder (`claudeHome`: `CLAUDE_CONFIG_DIR`, else `<home>/.claude`, as the machine joined the relay with it, and `<home>/.claude` for a machine the relay imported from a `devices/` record anyhost 0.1 wrote), Claude Code's temp root, Codex's home and the checkout, each in both the forms macOS gives a path under `/etc`, `/tmp` or `/var` (`/private/tmp/claude-501` and `/tmp/claude-501`: Claude Code writes the first, and prompts and tool calls hold the second too), and each encoded folder name that starts with one of them (`-Users-alice-app`, where the checkout's part wins over the home it sits in). That covers Claude Code's and Codex's own fields, tool results, the person's prompts and the model's text, thinking and tool calls, so a moved session reads as if it ran here, and restore adds no line. A boundary is any character but a letter, digit, `.`, `_` or `-`, read through JSON escapes. `.json`, `.jsonl` and the `state_5.sqlite` row change in their JSON-escaped form and other text files as plain text. `file-history/` backups keep their bytes, because `/rewind` writes them back into the person's files, and so do binary files, which hold a NUL byte in their first 8000 bytes (git's test).
- A rewritten conversation breaks nothing another party checks: the Messages API answers a conversation whose signed thinking or earlier turns changed with HTTP 200 and drops that thinking (`input_transformations` `thinking_dropped`, `prefix_binding_mismatch`), as it does in long sessions on this Mac, and Claude Code never re-hashes a stored `api-request-blob` or `api-request-shape`.
- Tests drive the program against `memoryRelay` from `cli/tests/memory.ts`, which serves the relay's WebSocket and HTTP routes as `relay/pool.ts` and `relay/worker.ts` answer them, from memory, with knobs that fail ops, delay or drop answers, and break downloads. Each test file stops its relays with `afterEach(stopRelays)`. Tests pass `noCode` to `openCapture` for the code stand-in, and restore onto the same roots, where `relocate` keeps every byte. `mock.module` is never used: Bun's module mocks leak into the other test files of the run, and a mocked `code.ts` failed 10 of `code.test.ts`'s tests.
- OrbStack's kernel has no socket destroy, so `ss -K` answers `RTNETLINK answers: Invalid argument` on a test machine. `iptables -I OUTPUT -d <relay address> -p tcp --dport 443 -j REJECT --reject-with tcp-reset` kills the program's socket from the network side at its next send instead.
- `fs.watch` with `recursive` hears new folders on macOS and on Linux. The program watches `projects`, `file-history`, `tasks`, `session-env`, `plans` and `paste-cache` under Claude Code's folder, Claude Code's temp root, `~/.codex/sessions`, and Claude Code's folder and Codex's home without recursion for the lines files. A watched folder Claude Code makes while the program runs, such as `tasks/` at a session's first task, is watched as soon as its parent's watcher names it, and every file it holds then is heard. It never watches `jobs/`, whose `jobs/<id>/tmp/` scratch trees reach 17 GB on this Mac.
- Bun's `Bun.file(path).writer()` writes over an existing file without emptying it, so a shorter write leaves the old bytes after it. Code that replaces a file opens it with `'w'`.
- OrbStack machines don't resolve Tailscale names, so a test machine reaches the pool at `http://devbox:8317` through an `/etc/hosts` line for devbox's Tailscale address.
