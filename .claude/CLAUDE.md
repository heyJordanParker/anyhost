# WHY

anyhost keeps every Claude Code and Codex session of every machine the Architect works on in Cloudflare R2, lists every session on every machine, and resumes a session on any machine from R2 alone, so a dead or busy machine never holds his history hostage.

# Facts

- The repository root is a cmod mod: `src/mod.ts` is the `defineMod`, `hooks/register.ts` only registers it, and `tests/` holds its `bun test` suite. `node_modules/@cmodjs/core/docs/` is the cmod documentation for the installed version.

A socket that brings no answer for 40 seconds (`ANSWER_MS`) while a request sent on it waits drops first, as the Pool answers pings without waking, and each answer starts the 40 seconds again, so a slow link that keeps answering keeps its socket, and a pong or another machine's message never counts as an answer. Cloudflare keeps listing a sleeping machine's half-open socket until a message sent on it fails, so the Pool counts a socket alive only while the last message it heard on it, which it keeps in memory, its last ping, which the platform records without waking the Pool (`getWebSocketAutoResponseTimestamp`), or its connect is within `LIVE_MS` (45 s, in `relay/protocol.ts`): only a live socket gets a message, `devices` answers `connected` from it, the clone check at a join and a connect counts only a live socket, and a routed message for a machine with no live socket answers `offline`. Cloudflare takes the whole Pool out of memory once no event ran in it for a short while, a message still on its way included, which forgets the message times, so `LIVE_MS` holds for the pings alone: a ping waits up to 10.49 s behind 1 MiB of uploads at 100 KB/s, so two reach the Pool at most 40.49 s apart, and 4.51 s is left for the link's own delay. A ping sent more than 34.51 s (`LATE_PING_MS` in `relay.ts`, `LIVE_MS` less 10.49 s) after the last one, as after the machine slept with its socket open, may reach the Pool after it counted the socket not live, when a take's `released` went only into `waiting`, and an idle machine's pings never wake the Pool to send it again.
